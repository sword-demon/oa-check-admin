# OA Check Admin — 产品文档

> 当前版本: **0.3.0.0** · RBAC 权限管理 + 审批流引擎后台管理平台模板

## 1. 产品定位

OA Check Admin 是一套可 Fork 即用的 **后台管理平台模板**，内置 RBAC 权限管理和 Flowable 审批工作流引擎。开发者运行一条 `init.sh` 脚本即可获得完整的权限 + 审批底座，并可在此基础上扩展业务模块（如请假、报销、采购等）。

**核心价值主张：**
- 开箱即用的 RBAC 权限体系（用户/角色/权限/部门四级管理）
- 可视化审批流程设计器（钉钉风格 Lowflow 设计 + BPMN 标准引擎）
- YAML 驱动的代码生成器，一条命令生成完整业务模块
- Docker Compose 一键部署，零配置启动

## 3. 功能矩阵

### 3.1 RBAC 权限管理

| 功能 | 描述 |
|------|------|
| 用户管理 | CRUD + 角色分配，支持状态启停 |
| 角色管理 | CRUD + 权限分配，支持数据权限范围配置 |
| 权限管理 | 菜单/按钮/API 三级权限树，树形可视化管理 |
| 部门管理 | 树形组织架构，支持父子级联关系 |
| 数据权限 | 全部数据 / 本部门 / 本部门及子部门 / 自定义 |

### 3.2 审批工作流

| 功能 | 描述 |
|------|------|
| 审批模板管理 | 创建/编辑/发布/取消发布/新建版本 |
| 动态表单设计 | JSON Schema 驱动，支持 9 种字段类型 |
| 可视化流程设计 | Lowflow 风格节点链设计 + BPMN 引擎双模式 |
| 发起审批 | 按模板提交表单数据，自动启动流程实例 |
| 我的申请 | 查看已发起的审批，支持撤回（首个审批人未处理时） |
| 我的待办 | 处理待审批任务，支持通过/驳回 + 审批意见 |
| 我的已办 | 查看历史已处理的审批记录 |
| 抄送管理 | 审批流程中的抄送通知，支持标记已读 |
| 条件分支 | 排他网关 + UEL 表达式驱动的动态路由 |
| 会签/或签 | 多人审批：全员通过 / 任一通过 |
| 审批人策略 | 固定人员 / 部门主管 / 上级主管 / 角色 / 发起人 / 表达式 |
| 审计日志 | 全流程操作记录，支持管理后台查看 |
| 仪表盘 | 待办/已办/模板/抄送统计 + 最近审批动态 |
| 站内通知 | 审批状态变更通知，待读/已读管理 |

### 3.3 流程设计器

| 能力 | 描述 |
|------|------|
| Lowflow 风格 UI | 钉钉式节点链设计，递归渲染审批/抄送/分支节点 |
| BPMN 双模式 | 设计态使用 Modeler，查看已发布模板使用 Viewer |
| 节点类型 | 开始 / 审批人 / 抄送人 / 条件分支 / 并行网关 / 结束 |
| 属性配置 | 抽屉式面板，按节点类型展示对应配置表单 |
| 发布校验 | 表单字段 + 流程连通性 + 审批人配置 + 版本校验 |
| 版本管理 | 已发布版本不可修改，基于旧版本创建新草稿 |
| 自动保存 | 30 秒防抖自动保存，页面离开未保存警告 |

### 3.4 代码生成器

| 能力 | 描述 |
|------|------|
| YAML DSL 定义 | 声明式定义实体、枚举、字段和关系 |
| 全栈代码生成 | Entity / Mapper / Service / ServiceImpl / Controller / Flyway SQL |
| 枚举生成 | 自动生成 Java 枚举类 |
| CLI 工具 | 支持 `--dry-run` 预览、`--flyway-only`、`--entity` 过滤 |
| 业务模块集成 | 生成的模块自动接入审批流和权限体系 |

### 3.5 请假模块（示例业务）

作为代码生成器的产物和业务模块参考实现，请假模块演示了完整的业务模块接入流程：
- 请假申请 CRUD
- 审批流集成（发起审批 / 审批回调）
- 状态流转（草稿 → 审批中 → 已通过/已驳回）

## 5. API 契约

- **风格**: RESTful，统一前缀 `/api/v1/`
- **认证**: Header `satoken: {token_value}`
- **统一响应体**:
  ```json
  { "code": 200, "msg": "success", "data": {...}, "timestamp": 1234567890 }
  ```
- **分页响应**:
  ```json
  { "code": 200, "data": { "list": [...], "total": 100, "page": 1, "pageSize": 20 } }
  ```

### API 模块

| 模块 | 路径前缀 | 描述 |
|------|----------|------|
| 认证授权 | `/api/v1/auth/` | 登录/登出/当前用户信息 |
| 用户管理 | `/api/v1/users/` | CRUD + 角色分配 |
| 角色管理 | `/api/v1/roles/` | CRUD + 权限分配 |
| 部门管理 | `/api/v1/depts/` | 树形 CRUD |
| 权限管理 | `/api/v1/permissions/` | 权限树 CRUD |
| 审批模板 | `/api/v1/approval/templates/` | 模板 CRUD + 流程设计 |
| 审批流程 | `/api/v1/approval/` | 发起/审批/撤回/抄送 |
| 管理后台 | `/api/v1/admin/` | 审计日志/实例管理/指标 |
| 通知 | `/api/v1/notifications/` | 站内通知 |
| 请假 | `/api/v1/leave/` | 请假 CRUD |

## 6. 安全体系

| 层面 | 实现 |
|------|------|
| 认证 | Sa-Token 会话管理，单设备登录 |
| 授权 | `@SaCheckPermission` 接口级 + `@SaCheckRole` 角色级 |
| 密码 | BCrypt 加密存储 |
| 审计 | 全操作日志记录 |
| 数据权限 | 按部门范围过滤数据 |

## 7. 部署方式

| 方式 | 说明 |
|------|------|
| Docker Compose | 一键启动 MySQL + Redis + Backend + Frontend (Nginx) |
| 手动部署 | Java JAR + MySQL + Redis + Nginx 静态资源 |
| 开发模式 | 后端 `mvn spring-boot:run`，前端 `npm run dev` |
